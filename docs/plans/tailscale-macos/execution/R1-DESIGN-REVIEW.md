# R1 design review: Tailscale foreground-session authority

**Purpose:** Owner decision brief for R1-A only. Read with the [DR-1 record](../../../../internal/tailscale/DR-1-session-authority.md) and [pinned source-evidence inventory](R1-SOURCE-EVIDENCE.json).

**Outcome:** Keep Tailscale Serve unavailable. The preferred *candidate* is a pinned LocalAPI watcher/session owned in-process by the long-lived relay, but no implementation option, platform support matrix, Go dependency, or local privilege scope is approved. The existing `ServeRouteOwned=false` behavior remains correct. This brief is source/design research only: no Tailscale CLI or daemon was run; no tailnet, app pairing, product code or runtime qualification was touched. `ownerApproved=false`, `runtimeQualified=false`, `featureReady=false`; R2 has not started.

## Trust and threat model

The cooperating-writer boundary is precise: each writer reserves and modifies only its own ephemeral watcher-session key. Relay selective registration/removal may modify only this run's `Foreground[sessionID]`; other routes, background fields and independent session IDs remain untouched by those writes and by upstream's single-key `DeleteForegroundSession`. Any writer that repurposes this run's ephemeral key violates the session-key noninterference assumption, even accidentally. If a changed/expanded same-key value is detected while L is live, fail closed: no cleanup write, no intentional watch cancellation, and retain O/control/records in quarantine. That leaves the observed value untouched only while L stays live. UP-003/UP-004 establish that any later watcher exit, including involuntary loss, may delete whatever then occupies that key before the relay observes the loss. Neither O nor quarantine fences that daemon action; same-key preservation on involuntary loss is outside the guarantee. Unconditional protection would require a different daemon primitive or maintained fork, outside R1 and not approved.

This is not a guarantee against a malicious same-UID/root/operator process, which can omit ETags, manipulate watches/keys or change other local state; LocalAPI write permission is broad, not Serve-only. O/T and a private socket are not that security boundary; the same file/TOCTOU assumptions remain shared with DR-2. The watcher/session ID is an in-memory run handle, not a secret token or portable capability. LocalAPI tokens and macOS same-user-proof material are sensitive: keep them in transport/memory, never in argv, environment, logs, session files or QR output.

## Proposed safety protocol (summary)

1. Read-only prepare: strict status, exact supported version, node/tailnet/DNS, HTTPS capability and complete Serve state. Reject unknown/extra/background/Funnel state, unsupported distribution, missing permission or any ambiguity.
2. Obtain explicit run consent.
3. Re-read and compare identity/version/Serve immediately after consent; require non-empty ETag and exact supported empty config.
4. Acquire existing managed owner O. Under an explicit managed-Tailscale constructor policy, use a proposed read-only `deviceauth.OpenDeferred`: validate/read existing state without creating/protecting/chmodding the directory or initializing/rewriting `devices.json`. Keep all E2EE resolver delegation closed until live owner and route readiness so no credential completion can persist early; after readiness, preserve normal existing credential behavior. Never expose the raw Store as the Hub's resolver. Start local listeners and private control in locally healthy, owner-held but pairing-unarmed state, with route mutation and L acquisition disarmed. Preserve non-Tailscale `Open` behavior and enrolled credentials. Only after the shell receives this in-process O-held status may it persist the selected transport/origin/run record.
5. On authenticated localcontrol `activate`, acquire L in that same relay process and keep its watcher/session in an opaque in-memory handle; submit one conditional registration POST only, with non-empty ETag and transport retries disabled. Classify the result as settled-success, settled-no-write, or unresolved; no timeout, truncated reply or empty GET resolves an in-flight write.
6. Confirm the live handle, exact route, unchanged identity/version, local listener, TLS and health. Keep local HTTP health distinct from `localcontrol.Ready`. Only then persist the invitation, open the bootstrap gate, and return a durable owner-side arm acknowledgement; no QR/link before it.
7. Monitor watcher, identity, route and health. Close the bootstrap gate before stopping the public listener on loss. A changed same-key value detected while L is live gets no cleanup write or intentional cancellation; quarantine O/control/records. On involuntary watcher loss, the daemon's deferred single-key deletion may already have removed whatever occupied that key before the relay observes the loss. Report same-key state as possibly deleted/unverified, not preserved, and do not infer route cleanup or retirement from O/quarantine. Other independent keys/routes/background fields remain outside that single-key action.
8. For deliberate orderly retirement, reconcile the whole `Foreground[sessionID]` value while L remains live. Conditionally remove only the exact submitted value with a fresh ETag, then require an acknowledged write and live-watcher readback showing absence before attempting local stream cancellation. If the key is changed/expanded, make no cleanup write or intentional cancellation; the observed value remains untouched only while L stays live, and O/L/control/records stay quarantined. Any subsequent involuntary watcher exit may still trigger unconditional deletion of that same-key value before notification; same-key preservation is outside the guarantee. For unresolved registration, absence remains unknown and only a later exact route can be selectively removed. Local request cancellation/body close/reader join proves only client-stream closure: UP-003/UP-009 provide no daemon-side watcher-close acknowledgement or finite cleanup deadline. Report route cleanup separately from watcher retirement; never return `retired=true` or release O based on local close or a final absent GET. Retain the owner and records as `unknown/not-retired` unless a separately reviewed retirement contract supplies a server-side acknowledgement. No global-empty inspect.

Detailed state transitions, exact invariants, failure policy, proposed numeric bounds and R2 synthetic test cases are in [DR-1](../../../../internal/tailscale/DR-1-session-authority.md).
