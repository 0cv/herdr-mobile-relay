# Collie and Herdr Mobile Relay: Tailscale architecture comparison

**Source snapshots:** Collie [`4283ca6560acd15138365d3e757046902b9fc480`](https://github.com/AltanS/collie/commit/4283ca6560acd15138365d3e757046902b9fc480) (2026-09-24); Herdr candidate [`f4aa97432f9048dac6df6211f9a45df0fcde323c`](https://github.com/0cv/herdr-mobile-relay/commit/f4aa97432f9048dac6df6211f9a45df0fcde323c). Research performed by an Astra Xhigh subagent from source, public documentation and release/CI metadata. The agent **did not run** either application, a daemon, a phone test, or a benchmark; it could not write files in its read-only research role, so the orchestrator recorded its analysis here. The Herdr comparison is frozen to the stated candidate SHA, not an assertion about future revisions. “Shipped” below refers to publicly released Herdr v0.22.0, not this unpublished branch.

## Executive assessment

**Collie is the more complete Tailscale-first workflow today.** Its CLI provisions a persistent background Serve mapping, starts a supervised Bun bridge, prints access/pairing information and supports lifecycle/update workflows. It can coexist with some existing Serve entries and offers an operator-owned ingress path. This is a source-level assessment, not a live compatibility certification. See Collie [installation](https://github.com/AltanS/collie/blob/4283ca6560acd15138365d3e757046902b9fc480/docs/install.md), [lifecycle](https://github.com/AltanS/collie/blob/4283ca6560acd15138365d3e757046902b9fc480/cli/lifecycle.ts), [Serve integration](https://github.com/AltanS/collie/blob/4283ca6560acd15138365d3e757046902b9fc480/cli/serve.ts) and [service units](https://github.com/AltanS/collie/blob/4283ca6560acd15138365d3e757046902b9fc480/cli/unit.ts).

**Herdr has the stronger default application authorization/confidentiality boundary.** Its keyed sessions require device enrollment and authenticate before WebSocket registration; its end-to-end encrypted frames retain protection across a TLS-terminating ingress, with controller/reader roles. Collie normally relies on tailnet HTTPS and optional trusted-person/device checks: its pairing factor gates *writes*, not reads, and if the pairing registry has no devices that factor stops being enforced. That is not the same as saying Collie has no access controls; the front-door identity gate may remain enabled. Compare Collie [server guard](https://github.com/AltanS/collie/blob/4283ca6560acd15138365d3e757046902b9fc480/bridge/server.ts), [pairing registry](https://github.com/AltanS/collie/blob/4283ca6560acd15138365d3e757046902b9fc480/bridge/pairing.ts) and [browser API](https://github.com/AltanS/collie/blob/4283ca6560acd15138365d3e757046902b9fc480/web/src/lib/api.ts) with Herdr [handshake](https://github.com/0cv/herdr-mobile-relay/blob/f4aa97432f9048dac6df6211f9a45df0fcde323c/internal/transport/e2ee.go), [Hub admission](https://github.com/0cv/herdr-mobile-relay/blob/f4aa97432f9048dac6df6211f9a45df0fcde323c/internal/transport/ws.go) and [device store](https://github.com/0cv/herdr-mobile-relay/blob/f4aa97432f9048dac6df6211f9a45df0fcde323c/internal/deviceauth/store.go).

**Herdr's managed Tailscale candidate is not yet integrated end-to-end.** Its in-process LocalAPI session authority, app gate and authenticated control exist and have a hosted protocol-fake positive integration test. But the [launcher](https://github.com/0cv/herdr-mobile-relay/blob/f4aa97432f9048dac6df6211f9a45df0fcde323c/relay/tailscale.sh#L264-L398) still starts an external `tailscale serve` child and waits for `serve_route_owned`, while [inspection deliberately never grants ownership](https://github.com/0cv/herdr-mobile-relay/blob/f4aa97432f9048dac6df6211f9a45df0fcde323c/internal/tailscale/tailscale.go#L95-L148). It has not been migrated to `local_ready → activate → arm_bootstrap → retire`; there is no validated extracted-package browser journey or real-daemon/phone qualification. Shipped Herdr v0.22.0 offers [Cloudflare and gateway choices](https://github.com/0cv/herdr-mobile-relay/blob/22895ee7765ba0129a6e21f2e9663d8cd7722cd6/relay/plugin-choose-transport.sh), rather than this managed path.

### Operational nuances

- Collie’s Linux service unit uses restart-on-failure with a five-second delay; macOS uses launchd KeepAlive-on-failure. Mac launchd does not inherit systemd’s confinement. Its `--bg` mapping persists separately from bridge lifetime. See [unit generation](https://github.com/AltanS/collie/blob/4283ca6560acd15138365d3e757046902b9fc480/cli/unit.ts) and [Serve](https://github.com/AltanS/collie/blob/4283ca6560acd15138365d3e757046902b9fc480/cli/serve.ts). This is useful availability, but do not copy a blind service restart into Herdr while a managed route is unresolved.
- Collie can adopt an already matching backend and checks mount/protocol conflicts; its stop does not necessarily unpublish ingress. A background route's persistence is intentional, but a matching backend/port alone cannot prove which process owns it. [Serve](https://github.com/AltanS/collie/blob/4283ca6560acd15138365d3e757046902b9fc480/cli/serve.ts), [lifecycle](https://github.com/AltanS/collie/blob/4283ca6560acd15138365d3e757046902b9fc480/cli/lifecycle.ts).
- A Tailnet URL alone does not establish phone-side ACL/DNS/VPN reachability. Plain tailnet HTTP loses the secure-context PWA/service-worker benefits; HTTPS certificates are a real prerequisite. [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve), [Collie tailnet checks](https://github.com/AltanS/collie/blob/4283ca6560acd15138365d3e757046902b9fc480/cli/tailnet.ts). Both approaches still require the mobile Tailscale VPN; it can conflict with another mobile VPN. [Tailscale VPN FAQ](https://tailscale.com/docs/reference/faq/other-vpns).
- Collie registry stores **hashes** of pairing tokens; Herdr stores symmetric per-device secrets in permission-protected files for its current cryptographic protocol. Copying hash-only storage without redesigning authentication is not a small patch. [Collie registry](https://github.com/AltanS/collie/blob/4283ca6560acd15138365d3e757046902b9fc480/bridge/pairing.ts), [Herdr store](https://github.com/0cv/herdr-mobile-relay/blob/f4aa97432f9048dac6df6211f9a45df0fcde323c/internal/deviceauth/store.go).
- Collie’s docs describe upgrade staging/rollback; implementation and deployment kinds differ. Neither a published release nor documented recovery is proof the researcher exercised it. [Upgrade guide](https://github.com/AltanS/collie/blob/4283ca6560acd15138365d3e757046902b9fc480/docs/upgrading.md).

## Performance and resource model (not benchmark results)

Collie’s backend polling defaults to about **1.5 s**, relaxing to **12 s** when its event stream is healthy; browser schedules include **300 ms** post-action bursts, **1.5 s** active-pane, **4 s** busy-dashboard, and **6 s** idle checks. Its browser request budgets include **10 s reads / 20 s mutations / 60 s uploads**. HTTP ETags and gzip reduce repeated body transfer, but polling still consumes requests and snapshot work. These are [source-configured intervals](https://github.com/AltanS/collie/blob/4283ca6560acd15138365d3e757046902b9fc480/bridge/config.ts) and [browser scheduling rules](https://github.com/AltanS/collie/blob/4283ca6560acd15138365d3e757046902b9fc480/web/src/hooks/use-polling.ts), **not observed user-visible latency**. Its compiled Bun runtime simplifies install but affects binary distribution; published v1.13.1 compressed release assets are roughly 29 MB Mac arm64 and 40 MB Linux x64/arm64 ([release metadata](https://github.com/AltanS/collie/releases/tag/v1.13.1)); archive size is not executable size, RSS or download-to-interaction time.

Herdr holds WebSockets and E2EE state instead of a mandatory periodic browser request. Its outbound queue is bounded at **64 items / 4 MiB per client** ([implementation](https://github.com/0cv/herdr-mobile-relay/blob/f4aa97432f9048dac6df6211f9a45df0fcde323c/internal/transport/sendbuffer.go)); that does not cap total process memory or clients. JSON/base64 ciphertext on the direct WebSocket adds encoding overhead; the binary gateway/WebRTC path differs. Its candidate authority revalidates periodically and adds a pinned LocalAPI dependency, increasing control-plane and maintenance surface without embedding a second daemon. No matched CPU, RSS, battery, throughput, reconnection or p95 action-latency benchmark exists here. **Neither “Go is faster” nor “polling is more resilient” is an established empirical conclusion.**

For a useful future comparison, fix the exact releases, machine, daemon variant, network path, phone/PWA, pane/transcript sizes and active devices; measure idle/active CPU/RSS, bytes/request counts, command-to-visible-result distribution, sleep/wake reconnection and mobile battery. No benchmark was run for this report.

## What to borrow, and what not to copy

1. **Finish Herdr’s launcher first.** Replace external Serve child and observation-based ownership with authenticated `local_ready → activate → arm_bootstrap → retire`, including lost-ack, held-output-pipe, restart, quarantine and protected credential paths. Do not set `ServeRouteOwned=true` based on inspection. This is a prerequisite for advertising managed Tailscale, not an enhancement.
2. **Offer a clearly separate BYO HTTPS/Serve mode for existing tailnet operators.** The historical [Fedora/Android working recipe](https://github.com/0cv/herdr-mobile-relay/issues/5) and [later script](https://github.com/0cv/herdr-mobile-relay/issues/5#issuecomment-5728994680) illustrate the demand. The script assumes an existing Serve route, merely warns on a mismatch, and does not claim managed ownership. In a supported BYO mode Herdr would own only its relay/app credentials: no Tailscale login, LocalAPI mutation, route cleanup or anti-port-reuse promise. Require explicit HTTPS origin and real endpoint/identity readiness before claiming pairing success; stopping leaves operator-owned ingress configured. **Do not relabel this as managed mode.** Documentation-only guidance is low-cost; verified installer/service UX is moderate; reproducing managed guarantees in BYO mode defeats its simplicity.
3. **Borrow operational diagnostics** distinguishing local backend health, public HTTPS reachability, tailnet prerequisites, installation/supervision type, externally owned Serve and actionable refusal. Avoid using a matching port, text status or URL as proof of route/session ownership. Collie’s adaptive work/sleep-wake scenarios are good candidates for Herdr regression tests, not evidence to replace WebSocket with polling.
4. **Retain Herdr’s independent device authorization, reader/controller permissions, E2EE and fail-closed enrollment.** Do not import an empty pairing-registry → no pairing-required rule. A public-key credential redesign might reduce at-rest symmetric-key exposure, but is a separate protocol project, not a Tailscale integration shortcut.
5. **Treat Mac variants and packaging as distinct qualification cells.** Collie delegates to an installed CLI; Herdr’s current private LocalAPI adapter supports neither GUI MacSys nor App Store. An exact experimental MacSys transport is not observed runtime support. Require extracted-package browser acceptance and, separately, authorized real-daemon and physical-phone testing before a production qualification claim.
6. **Do not import crew federation or automatic restart solely for parity.** They solve separate multi-host/availability goals and expand trust, state and unresolved-cleanup complexity. Herdr’s independent phone-to-relay aggregation is a defensible alternative.

## Evidence limits and latest Herdr CI

At the frozen Herdr candidate SHA, [ordinary check run 36103347565](https://github.com/0cv/herdr-mobile-relay/actions/runs/36103347565) and [native preflight 36103347391](https://github.com/0cv/herdr-mobile-relay/actions/runs/36103347391) are reported successful. Ordinary Go/race, tagged normal/race app-control and frontend checks passed; **mobile harness/device jobs were skipped**. The tagged integration runs real app authority/gate/store/E2EE against a disposable raw LocalAPI and trusted TLS fixture, not a real daemon or installed phone. Native lifecycle jobs use synthetic/inert fixtures. No extracted-release Tailscale launcher/browser gate exists yet. Previous red candidates do not override the latest green status, and latest green status does not qualify real MacSys, tailnet certificates, iOS/Android or physical-device push behavior.

Collie source/release documents were inspected statically; this report does not certify its release asset signatures, macOS installation variant, live Serve cleanup race behavior, or mobile performance. Especially for route-adoption/TOCTOU and malformed pairing registry, the analysis identifies source-level boundaries, **not a reproduced exploit**. One must not infer that Collie lacks mobile pairing or multi-host support from older marketing text: current source has both optional pairing and crews.
